# ADR-0005: Cover image sourcing order and hotlinking

* Status: accepted
* Date: 2026-10-25

## Decision

Cover candidates are proposed in this order:

1. **Official page image:** `og:image` or the JSON-LD `image` of the user's URL (or of an official
   source the research stage cited), validated by the SSRF-safe fetcher (reachable, image content
   type).
2. **Wikimedia Commons:** MediaWiki API `generator=search` in the File namespace with
   `prop=imageinfo&iiprop=url|extmetadata`. Only free licences (CC0, CC BY, CC BY-SA, public domain)
   are kept, and artist, licence and file page are recorded for attribution. No API key is needed.
3. **Unsplash** (if `UNSPLASH_ACCESS_KEY` is set): `/search/photos`, hotlinked `urls.regular`,
   attribution "Photo by {name} on Unsplash" with UTM links, and the download endpoint triggered when
   the user selects the photo, as Unsplash's API guidelines require.
4. **None:** the client renders a neutral, type-specific placeholder.

Users can also paste an image URL (validated server-side) or upload a JPEG, PNG or WebP of up to
5 MiB, which is stored in PostgreSQL.

## Rationale

* An official imagery match is the most relevant, and rights to show it as a bookmark preview are
  the same as for a link preview. We store the URL, not a copy.
* Wikimedia gives clear licence metadata and broad coverage of Polish landmarks.
* Image URLs are never generated by the model. The AI may only suggest search terms.

## Consequences

* A hotlinked image can disappear. The client falls back to the placeholder on `onError`, and the
  user can pick another cover at any time.
